# Kidoo Community separation: implementation and verification plan

**Status: Community implementation tested; release and historical-ref review remain.** The working checkout removes the online catalogue, download and playback implementation and rejects retired routes. Formerly public code may remain in third-party copies or caches. Community tests, offline migration tests and real local and Jellyfin playback/resume pass. A separately named test app was checked on a Fire TV and then removed; the original app and household server were not altered. The split does not retract anything already published. The owner has adopted the Kidoo Community Licence; independent legal review remains advisable.

## Target outcome

Community is a standalone, source-available family application for local and Jellyfin content. It retains child profiles, protected parent access, approvals, viewing limits, viewing history, resume, favourites, search, recommendations, Show less, Your TV and the parent dashboard. It does not contain YouTube catalogue or channel data, YouTube playback/download/import code or APIs, online review workflows, or UI controls for them. Premium source and future Premium work stay outside the public Community repository.

An implementation is not complete if YouTube is merely hidden in the interface while its code, catalogue or usable server endpoints remain in Community. Conversely, the word “YouTube” can still legitimately appear in a historical migration explanation, legal review or explicit statement of Community's exclusion; absence must be checked by path, behaviour and source review, not a blind text search alone.

## Baseline and safeguards

- Work in the maintained clean Community checkout, preserving the existing uncommitted work. Before editing a shared file, compare its changes with the private Premium snapshot and record what belongs in each edition. Do not overwrite or publish private work as part of the split.
- The current private snapshot contains the installed server source and the latest local TV source. The TV source has **not** been verified against the installed APK; the snapshot is not a backup of the live database, media, TLS keys or configuration. Keep existing private backups; do not use the family's running service as a test fixture.
- Do not restart, deploy to, pair with, migrate, or alter the existing home server, Fire TV, family profiles, approvals, content, viewing history or resume positions. A later device test or deployment needs the owner's authorisation and an explicit plan.
- Use isolated temporary directories, an isolated local server, generated non-sensitive metadata and a separate emulator or test device. **Do not create or play synthetic videos.** Use fictional labels or artwork only as test data, with no actual video file; for a real playback/seek test, use a rights-cleared real sample expressly available for that purpose, isolated from household state. If none is available, report playback as unverified rather than inventing evidence.
- Work without publishing until the Community tree, tests, documentation, third-party notices and privacy review pass. Do not push or upload the private snapshot. The owner has approved the Community licence. Continue the third-party rights and release review.

## 1. Freeze the edition boundary

1. Record the intended local/Jellyfin-only feature matrix and which existing files contain shared functionality versus YouTube-specific implementation. The current `server/kidoo_server.py`, `server/your_tv.py`, `server/security.py`, `server/time_limits.py`, `server/dashboard.py`, browser UI and Android TV player all contain both. Preserve shared protected access, viewing limits and YouTube-independent functionality while separating them.
2. Confirm the private server snapshot's core source files match the installed release, and keep its provenance note. Do not claim the copied TV source is the installed APK. Preserve any additional Premium-only work privately before removing it from Community.
3. Define a Community API contract for local and Jellyfin items, series, progress, ratings and Your TV. Specify which legacy endpoints return `404` or `410`, and version any incompatible client/server contract. Do not silently route a removed online request to a source website.

**Done when:** a reviewer can identify what will remain, what moves out, what was previously public and what has not been verified about the Premium snapshot.

## 2. Separate the server and data model

1. Remove the YouTube data and executable integration: discovery catalogue, channel mapping and verified-ID files; channel feed/review/import; online recommendations and tag enrichment; YouTube temporary playback, cache, maintenance, preparation and prefetch. Retain shared modules or functions only after extracting the parts needed for local and Jellyfin content. Separately installed yt-dlp, Deno and FFmpeg on the home server are not touched.
2. Remove the online API routes and requests from `server/kidoo_server.py`: online catalogue, search, discovery, recommendations, channel reviews, online approval/preference, playback/temp/download/prefetch and favourite operations. Ensure parent and child requests to retired URLs cannot start a process, contact an external service, disclose the old catalogue or access a previously saved online media URL.
3. Refactor the remaining home, search, recommendation, activity and progress paths so local/Jellyfin content, artwork and series grouping do not depend on online settings or catalogue IDs. `server/tv_catalogue.py` and `server/dashboard.py` currently mix these concerns and need targeted extraction rather than wholesale deletion.
4. Keep limits' overall and applicable local categories, including blocking, live expiry, pause accounting, midnight reset and shared-profile concurrency. Adapt category settings and dashboard output without weakening the existing limit enforcement. Remove online category operations from the Community API and UI only as part of a consistent migration.
5. Keep `server/your_tv.py` channel definitions, queues, offers and completion handling, with only local and Jellyfin candidates. Activate and adapt the previously prepared Community defaults/conversion helper after the server contract is ready. Filter unsupported saved sources and queue entries on a **copy** of legacy data; preserve the order and progress of eligible items. Disable online-only channels instead of silently choosing unrelated content. Channel selection must never itself grant approval; revocation and limits must still be checked before playback and transitions.
6. Design a versioned, transactional migration for a **copy** of an earlier Community database. Preserve profiles, local/Jellyfin approvals and blocks, parental access and pairing, progress, favourites, content reviews, limits, session history and channel definitions where compatible. Explicitly define whether legacy online records are retained as inaccessible archival data or omitted from the copy; never silently delete them from a source database. Back up and test rollback, interrupted migration and repeat execution. Do not copy or migrate the installed Premium database.

**Progress:** Online-specific modules, catalogue files and retired API handlers were removed from this working checkout and preserved in the private Premium area. The home response and Your TV accept local and Jellyfin candidates only; legacy online dashboard records are excluded. `server/community_migration.py` offers both a copy and an explicit stopped-server upgrade with schema/integrity checks, an exclusive verified backup, a staged transaction and atomic replacement. Historical online records remain archived. Tests cover repeat upgrades, profile data, credentials, limits, sidecars, changed sources and interruption before replacement. The operator must stop all writers: the tool cannot prove they are stopped. No family database has been migrated.

**Done when:** the server starts without online-only modules or data, preserves approved local/Jellyfin behaviour, refuses removed endpoints and passes migration/rollback tests on isolated copies.

## 3. Adapt the parent dashboard, browser and TV app

1. Remove YouTube navigation, discovery, tag search, channel greenlighting, online review queues, external-source links and temporary-playback controls from `server/home/` and Android TV. Remove the online category from search, settings, viewing limits and summaries only after the server contract changes in step 2. Keep ordinary local/Jellyfin title review and per-profile approval.
2. Update `MainActivity.kt`, `PlayerActivity.kt`, shared models, API client and journals so home shelves, search and the player accept only supported local/Jellyfin media. Retain movie/series separation, series-to-episode navigation, suitable portrait/landscape artwork, playback controls, favourites and resume. Remove online-specific request paths, fallbacks, imports and unreachable UI code rather than shipping dormant Premium implementations.
3. Retain the Your TV grid, channel artwork, three-item persistent queues, completion/refill, next preview and Continue watching for the last unfinished **item**, not the channel. With no eligible items, show a useful empty state without suggesting an unsupported source. Handle an unavailable local or Jellyfin item without bypassing approval.
4. Preserve remote-control focus, readable text, scroll behaviour, search and the parent settings icon. Parent/child visual differences and server-enforced permissions remain independent of the removal.
5. Adapt dashboard screenshots and demo fixtures to rights-cleared, fictional metadata with no video files or real family records. Dashboard screenshots already exist locally; they do not substitute for missing native TV screenshots or a real interface recording. Never label mockups as actual app captures.

**Progress:** The TV app's home, search, player and Your TV accept local/Jellyfin content, and the dashboard no longer shows online review controls or an online limit. Android debug build, unit tests and lint pass. The dashboard was inspected with fictional metadata. A separate Community test app played and resumed a real title through an isolated Jellyfin instance on a Fire TV, and Your TV played that title; the test app was then removed.

**Done when:** the TV and browser display only supported sources, provide no route or control that opens an online source, and continue to serve the selected profile's authorised media and parent functions.

**Evidence so far:** 39 Community tests pass with both real-media tests enabled. They cover retired routes, forged online operations, child/parent and profile isolation, approval and device revocation, Your TV queues and safe repeats, limits and local-midnight daylight-saving boundaries, archived data, offline migration and interruption recovery, PINs and pairing. Android debug build, unit tests and lint pass. The parent dashboard was inspected using fictional metadata. A one-item physical TV test does not cover multi-item transitions or every codec and failure; no real household database was upgraded.

## 5. Review public branches and history separately

1. Inventory remote branches, tags, releases and current/earlier commits **read-only**, distinguishing code and assets the owner wants private, demo media without redistribution permission, and any personal information. Avoid printing or putting sensitive findings into a public document; keep any detailed report private.
2. Prepare alternatives with their effects: a new removal commit keeps prior Git history accessible; unpublishing branches/tags or rewriting history changes shared references and can disrupt other clones and integrations. Neither option recalls existing forks, cached copies, downloads or screenshots.
3. Preserve an offline private recovery copy and document the exact proposed refs and impact before any history operation. Ask the owner to approve a specific, reviewable operation before force-pushing, deleting remote refs, changing repository visibility or publishing a rewritten history. Do not conflate source-code removal with personal-data cleanup.
4. After an approved change, verify public refs, default branch, tags and releases, and report residual exposure and limits. Do not claim that independent copies have been erased. The local clean Community checkout remains the standard working tree; the Premium snapshot stays outside it.

**Progress:** on 4 November 2026, the Community tree was moved to a new public repository with a clean history. The former repository, including its six historical pull-request references, is a private archive. The previous public material may still exist in prior clones, third-party copies or caches; making the archive private does not recall those copies. The maintained checkout follows the clean Community history. A local pre-push check helps prevent retired commits from being reintroduced from that checkout; it does not control other clones or replace a review before publishing.

## 6. Finish documentation and release readiness

Update the README, setup guide, API docs, architecture/Your TV notes, licensing and rights inventory to distinguish **current** from **planned** behaviour and explain the Community scope. Do not accidentally include a Premium implementation, real addresses, credentials, viewing records or unlicensed demo media. Verify applicable Apache, MPL and Outfit notices and the exact source/notice requirements for packaged artifacts. The owner approved the Community licence; legal review and third-party rights verification remain open.

**Release gate:** Community source and build exclude the online integration; local/Jellyfin, child safety, dashboard, limits and Your TV pass the checks above; the demo media is rights-cleared; unsupported tests are disclosed; the installed Premium system is unchanged; and the owner has reviewed the exact changes and decided how to handle already-public history. Until then, no Community completion or private-history claim should be made.
